> **Nawigacja:** [tests/README.md](../README.md) → Ten dokument

## Overview

<!-- AUDIT-COUNT: total=116 runall=115 -->

These scripts enforce SSOT compliance, architectural boundaries, security, and code quality. Almost all run via `npm run audit:all` (`run-all.sh`), which is also invoked by `npm run git:push` before pushing. Most have a named `audit:*` npm script (one per `.sh`); a few run via `audit:all` only, with no named script (`endpoint-completeness`, `handler-method-consistency`). One advisory exception runs separately: `audit:stale-artifacts` (not in run-all, does not block push). **The `AUDIT-COUNT` marker above is the only place the counts live** — `audit-count.sh` (meta-guard) fails the build if run-all / package.json / .sh files / this marker drift apart, so this prose stays count-free on purpose.

> ⚠️ The pre-commit hook does **not** call `run-all.sh`. It runs a **targeted subset** based on staged files (kernel / web-1 / main) for fast per-commit feedback — see [`scripts/hooks/pre-commit`](../../scripts/hooks/pre-commit). The full audit suite gates at `git:push`.

### Zanim dopiszesz nowy skrypt

Strażnik jest uzasadniony, gdy spełnia **wszystkie trzy**:

1. **Klasa REALNIE odrosła** — nie „mogłaby odrosnąć". Poprawiłeś ją co najmniej raz
   i widzisz, że wraca. Prewencyjny ratchet na klasę, która wystąpiła raz i wynikała
   z jednorazowej migracji, to koszt bez zysku.
2. **Nic innego jej nie widzi.** `tsc --noEmit` (strict, `exactOptionalPropertyTypes`,
   w web-1 też `noUncheckedIndexedAccess`), ESLint (`no-restricted-imports` /
   `no-restricted-syntax` / jsx-a11y — obie konfiguracje z `--max-warnings 0`) i Vitest
   stoją w tej samej bramce co audyty. Reguła wyrażalna w ESLincie **należy do ESLinta**:
   dostaje prawdziwe AST zamiast grepa (grep łapie ją też w komentarzu i w stringu —
   `": any"` w komentarzu blokował kiedyś push przy czystym `tsc`) i pokazuje błąd
   w edytorze, a nie dopiero na bramce. Wyjątek, który uzasadnia skrypt: `.shared-kernel/`
   nie jest lintowany przez nic (root nie ma konfiguracji ESLint, a oba submoduły
   ignorują `READONLY-shared-kernel/**`), więc reguły sięgające kernela zostają tutaj.
3. **Ma FIXTURĘ, nie tylko teeth-test w sesji.** `tests/audit/_fixtures/<audyt>/`
   z próbkami `must-fail/` i `must-pass/` (plus `.expect`, żeby czerwień była z
   WŁASNEGO powodu). Teeth-test odpalony raz w sesji nie zostawia śladu i nie broni
   przed tym, że następna edycja skryptu go oślepi — a to nie jest hipoteza:
   ratchet gwiazdek dopasowywał współrzędne jednej ścieżki SVG, a ratchet tintów
   wymagał złota na pierwszej pozycji `color-mix`, więc oba raportowały zieleń nad
   żywym długiem. **Strażnik bez fixtury jest kandydatem do usunięcia, nie do zaufania.**

### Floor obecności (obowiązkowy)

Audyt, który nie znalazł ŻADNEGO wejścia, **nie melduje sukcesu**. W pomiarze S102
62 ze 106 skryptów zwracało zero uruchomione na pustym drzewie, a w historii repo
odziedziczone `GIT_DIR` po pushu z submodułu skierowało audyty na `.git/modules/<sub>`
i 54 ze 101 świeciły zielono nad nieistniejącym drzewem. Dwa narzędzia z `_utils.sh`:

- `require_source_dir "$DIR" "opis"` — katalog źródłowy musi istnieć i zawierać pliki;
- `require_scanned "$N" "opis"` — zbudowana lista wejść musi być niepusta.

`get_project_root` rozwiązuje root z **położenia `_utils.sh`**, nie z `git rev-parse`,
więc żadna zmienna środowiskowa nie przestawi go na inne drzewo.

Zieleń nad pustką **bywa poprawna** — dla skanu czysto negatywnego („zero wystąpień
zakazanego wzorca") zero trafień to prawidłowy wynik. Dlatego floor stawiamy na
**zbiorze wejściowym** (czy było co skanować), nigdy na liczbie trafień.

### Kiedy strażnik ma zniknąć

Usuń go (git zachowa historię), gdy zachodzi którekolwiek:

- **Klasa stała się niemożliwa** — typ, sygnatura albo rejestr wymusza poprawność
  na poziomie kompilacji. Wtedy strażnik pilnuje czegoś, czego nie da się złamać.
- **ESLint/tsc dostał regułę pokrywającą to samo** i obejmuje ten sam zakres.
  Zanim usuniesz: wstrzyknij naruszenie i sprawdź, że **nowe** narzędzie je łapie —
  tak usunięto `interactive-element-a11y.sh` (dowód: `jsx-a11y/click-events-have-key-events`
  + `no-static-element-interactions` łapią tę samą próbkę na AST).
- **Jest bliźniakiem innego** — ta sama reguła z podmienioną ścieżką. Scal i sparametryzuj
  (`circular-deps.sh` + `circular-imports.sh` → jeden skrypt z pętlą po workspace'ach).
  **Uwaga: wspólny szkielet to NIE to samo co bliźniak.** `deploy-artifact-identity`
  i `deploy-origin-parity` mają podobną budowę, ale pilnują dwóch różnych właściwości —
  scalenie takich reguł produkuje plik w rodzaju `tint-discipline.sh` (1126 linii,
  dwanaście rozłącznych reguł), czyli lek gorszy od choroby.

Czego **nie** jest powodem do usunięcia: sama liczba skryptów. Cały pakiet chodzi
~16 s — dla porównania ESLint na samym `main/` kosztuje ~42 s. Koszt tego katalogu
nigdy nie był czasowy; był nim brak dowodu, że strażnicy cokolwiek mierzą.

## Notes on specific audits

- **`imports-health.sh` ≠ cycle detection.** It guards module boundaries (READONLY kernel, cross-imports, Prisma SSOT, facade encapsulation). Value/runtime import **cycles** are owned by one madge-based ratchet: `circular-imports.sh` (main/src + web-1/src).
- **`docs-ssot.sh`** scans **production code only** — `docs/` is intentionally not scanned (analysis/review files legitimately quote the old domain/brand while documenting its fix, which caused false-positives and a rotting exception list). Placeholders (`[COMPANY NAME]` etc.) are a **warning**, not an error,.
- **`events-i18n-parity.sh`** checks **locale parity** (every event key present in pl/en/de), not "every `APP_EVENTS` event must be translated" — the user-facing/internal boundary is fuzzy and an allow/deny list would rot. `events.json` is the source of which events carry a user-facing string.
- **BDX ratchets (W1–W4, D1)** lock backend convergence wins so they cannot re-drift: env/secret governance, `@`-aliases, direct-Prisma (D1), handler shape, `_IO` suffix, the DB-failure idiom, kebab filenames, the sweep-interceptor factory, and zero value-cycles.

## Usage
